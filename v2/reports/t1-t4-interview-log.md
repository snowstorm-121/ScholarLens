## T1：让本机真实问答闭环跑起来

### 1. Qwen3 开了关闭 thinking 参数，仍未完成最终答案【实际观察】

- **现象**：原 `qwen3:4b` 在 512 和 2048 输出上限下继续长推理，未完成引用协议要求的最终答案。
- **排查**：对照原生 API、稳定运行时和模板变体，判断不是只修改 UI 配置就能解决；不能把上限耗尽或空最终答案当成功。
- **处理**：在已有诊断无效后改用官方非思考权重 `qwen3:4b-instruct-2507-q4_K_M`，固定实际型号、digest 和运行时。
- **验证**：同一个 train 事实问题实际回答 VQA 1.0 release，并解析到检索证据；原始失败保留于 `artifacts/t1/smoke-first-empty.json`、`smoke-2048-truncated.json`，成功见 `smoke.json`。
- **边界**：这是更换模型后的可行性闭环，不能声称“仅加 think=false 就修复”，也不能将换模型前后的成绩当单变量实验。
- **面试要点**：配置支持、模型实际行为和输出协议完成度，要分别检查。

### 2. 小模型不稳定遵守复杂引用协议【实际观察，部分缓解】

- **现象**：上游较复杂的引用 prompt 在小模型上没有稳定完成协议输出。
- **处理**：缩短本地 prompt，但保留原 inline citation 协议，继续复用解析与原文高亮，而不是绕开引用检查。
- **验证**：版本事实题输出非空答案、可解析引用和 context 中的对应原文，网页也显示高亮。
- **边界**：只证明该样例可跑；T5 仍出现协议外前缀，不能宣称引用格式从此可靠。
- **面试要点**：工程上的协议合规需要单独验收，不能只看答案像不像正确。

### 3. 宽泛问题漏证据，含数字问题过度拒答【实际观察，未全面解决】

- **现象 A**：`What benchmark datasets they use?` 未召回 GeoQA 的直接证据，多证据诊断失败。
- **现象 B**：context 已有 `more than 200,000 images`，模型仍因没有精确数值或下界而拒答。
- **处理**：分别保留检索不足和生成过度拒答，不将二者统称模型坏了；用范围明确的版本事实题完成可行性 smoke，但不替换掉失败记录。
- **验证材料**：`smoke-instruct-overrefusal.json`、`smoke-instruct-bound-refusal.json`、`smoke-short-prompt-refusal.json`。
- **边界**：没有据此证明要加 reranker/Hybrid，也没有得到整体问答质量提升结论。
- **面试要点**：先检查证据是否进 context，再判断是召回还是生成问题；展示成功样例不是质量评测。

### 4. 模型断连不能伪装成答案或正确拒答【实际观察，T5 完善】

- **现象**：当时停止 Ollama 服务，网页报错；后端为 APIConnectionError / RetryError，上游还会重试并遗留 Thinking 占位。
- **处理**：T1 验证不生成新答案、不回退 Mock；恢复服务后重跑同一 smoke。
- **验证**：`ui-disconnected.jpg`、`disconnect-backend.log`；恢复后的事实与引用检查通过。
- **边界**：T1 尚无完整友好错误分类；离线、超时、空输出和截断的独立 audit 是 T5 的工作。
- **面试要点**：系统失败与业务拒答必须分开，否则拒答率和成功率会失真。

### 5. 依赖检查不干净，但也不能直接认定程序无法运行【实际观察，警告保留】

- **现象**：`uv pip check` 返回 1，grpcio-tools 1.62.3 的 WHEEL 标签为 x86_64。
- **排查**：检查实际 extension 为 universal x86_64/arm64，原生 `protoc --version` 可运行。
- **处理**：保留警告和验证依据，不改安装元数据把检查“刷绿”，不扩大为整套环境重装。
- **边界**：不能写成依赖检查全部通过；本次功能能运行，也不代表所有依赖组合均无风险。
- **面试要点**：区分元数据兼容警告与实际运行失败，诚实保留环境限制。

### 6. CLI 服务迁桌面应用，磁盘占用不能按目录体积相加【实际操作与资源排查】

- **需求与现象**：用户希望桌面可视化管理，随后发现占盘变大；临时运行时、模型备份和安装包并存。
- **处理**：先安装同版本官方桌面应用，校验安装包哈希、codesign/spctl；APFS 克隆复制已有模型，不重下。停止旧服务，确认端口由桌面应用提供、模型 digest 不变，再重跑问答。
- **清理**：经授权删除项目内两个旧运行包、旧模型备份及安装临时文件；移除未使用的原始 qwen3:4b，清理 uv 缓存，保留正在使用的 Instruct/Nomic、环境、数据和实验记录。
- **验证**：清理后同一问答 smoke 仍通过。`df -k` 实测增加约 4.33 GiB；APFS 克隆共享块，因此目录显示大小不能相加当作实际可释放空间。
- **边界**：上述是历史状态。桌面应用可更新，登录会话设置也会变化，正式实验前需重新核对，不能当永久配置保证。
- **面试要点**：迁移先保持模型身份与接口一致，再清旧副本；性能进程 RSS 也不能冒充包含独立模型服务的总内存。

## T2：数据不只是下载，还要能定位、隔离和重放

### 7. 官方数据有一篇空正文，批处理会中断【实际观察并修复】

- **现象**：全量转换遇到 train 论文 `1801.07804`，`full_text=[]`，触发 MissingBodyError；关联 3 道题无法作为完整论文问答材料。
- **处理**：先复现，再仅对已知缺正文类型明确隔离到 rejected_papers 和报告；单篇转换仍严格报错，未知解析错误仍终止。
- **验证**：全量留下 1,584 篇、5,046 道原始待筛问题；测试 `test_missing_body_explicitly_quarantined`、`test_missing_body_raises`。
- **边界**：未补造正文、未用摘要假装完整论文，也不把所有异常都 catch 后继续。
- **面试要点**：可预期脏数据应有明确隔离策略，不是无条件容错。

### 8. 证据并不都能映射到唯一正文段落【实际数据问题】

- **现象**：7,990 个参考标注中 1,388 个未通过；原因包含图表/FLOAT SELECTED、空证据、全文无完整段落、同文多处出现。原因可重叠，不能直接相加当独立标注数。
- **处理**：正文规范化规则固定为 NFC/空白折叠，段间保留两个换行；只接受整个段落精确且唯一匹配。保存 paragraph_id 与 Python Unicode 字符半开区间，逐条检查切片等于 evidence_text。
- **验证**：映射到 6,602 个有效标注；重复文本、子串、错误 span 与图表证据都有测试，诊断保留在 `data/qasper/v0.3/mapping_issues.jsonl`。
- **边界**：不能取第一次命中或模糊匹配来掩盖歧义；全文字符 span 不是 PDF 页码、字节或 token。
- **面试要点**：定位首先保证可复核，宁可暴露未映射，也不伪造精确位置。

### 9. 不能删除难证据，把残缺参考组洗成正确 gold【数据语义约束】

- **问题**：同一参考的多段证据可能缺一不可；不同标注员参考组又是可替代的。如果扁平化成一个列表，会改变评测语义。
- **处理**：组内保留全部互补证据，任何一段不合格则该组无效；组间独立保留，某组无效不自动毁掉其他完整有效组。合法无答案参考允许空 evidence。
- **验证**：`test_incomplete_group_is_not_silently_shortened`、`test_alternative_annotations_remain_separate`、多证据与无答案测试。
- **边界**：这是明确的数据处理规则，不冒充发生过线上错误；完整证据组的实际检索指标是后续任务。
- **面试要点**：gold 结构决定指标含义，必须先定义 AND/OR 关系再算命中。

### 10. 发布包、重复运行和答案泄漏的风险【预防性约束】

- **风险**：包路径越界、重复键/ID、缓存内容变化、重复转换追加记录、问题答案误入知识库。
- **处理**：固定下载来源和本地 SHA-256，内存读取指定 JSON，拒绝越界/链接/重名；白名单导出论文正文，题目和标注独立保存，未知字段不自动透传到 Document。
- **验证**：27 项 T2 测试覆盖哈希、归档、ID、无 QA 泄漏和防覆盖；100 篇预览后全量转换，多次哈希及计数一致。
- **边界**：固定下载字节的哈希不是发布方签名；179 MiB 转换结果含原始/规范化文本，比压缩包大不等于又下载了模型。
- **面试要点**：可重现与防泄漏是建库入口的约束，不要只靠使用者记得别传错文件。

## T3：评测集不是抽够数量就可信

### 11. 标注员对可回答性有冲突，简单合并会污染金标准【实际数据问题】

- **现象**：dev/test 分别有 75/164 题回答性冲突；另有 125/114 题没有完整有效参考。
- **处理**：任一原始标注在 unanswerable 上分歧就整题排除，即使冲突一方后来证据无效；仅保留完整有效参考。规范化后按 paper_id + question 去重，跨论文同问法不自动当重复。
- **验证**：合格 dev 805 题、test 1,172 题；test 去重排除 1 题。冲突、无效组、去重和配额不足测试均覆盖。
- **边界**：保守筛选会改变数据分布；不能据此说保留下来的 gold 已全部语义正确。
- **面试要点**：回答性标签与证据定位是不同校验层。

### 12. 抽样可重现，也要防止冻结后悄悄改题【预防性约束并验证】

- **处理**：按 `SHA256("42|" + question_id)` 稳定抽样；检索 Dev/Test 为 200/300，生成 50/100 是各自子集，唯一题数是 500，不是 650。
- **保护**：保存输入、规则、代码和输出哈希以及选中 ID；重复 freeze 不更新时间戳或覆盖变化文件；变更需新版本。只冻结数据抽样配置，不误锁后续检索/模型实验配置。
- **验证**：T2/T3 共 48 项测试；官方兼容格式解析到 200/300/50/100 题，未调用评分；文件篡改、规则变化及新版本保留旧文件均覆盖。
- **边界**：Test 做结构/标注处理不等于运行系统 Test；没有根据系统输出挑题。冻结哈希见原报告。
- **面试要点**：freeze 不是文件名叫 test，而是改变会被检测、旧版本不会丢失。

### 13. span 正确，答案仍可能缺少语义依据【辅助审查发现，风险保留】

- **现象**：用户委托助手检查固定 30 道 Dev、50 个参考组，得到 19 supported、8 reference_risk、3 uncertain；不是准确率。
- **案例 A**：`17a1eff7…` 的一组将相关介绍中的 word intrusion 与本研究实际使用的 SEMCAT 都写成所用方法。
- **案例 B**：`8060a773…` 一组证据只说数字见表，却没有答案数字 23085，且数据范围不一致；不能断言原表没有数字，但纯文本参考组支持不足。
- **处理**：补读同论文相关正文，逐组记下依据、风险与不确定性；不修改冻结 v1、不根据 Dev 疑点修补 Test。
- **验证材料**：`reports/t3-review.md`、`artifacts/t3/v1/assistant-review.json`。
- **边界**：30 题全是可回答题，不覆盖无答案标注；助手审查不是人类独立审核，也不是独立模型盲审。没有把用户核验项伪造勾选。
- **面试要点**：精确匹配只能保证证据存在，不能自动保证证据支持答案。

## T4：多存储、检索作用域与实验一致性

### 14. 传 node_ids 不代表 Chroma 真做论文隔离【源码发现并测试验证】

- **原因**：锁定版本上游 Chroma adapter 忽略 node_ids；全库 Top-k 后过滤也会被其他论文挤掉正确候选。
- **处理**：BM25 仅加载该论文 chunks 建统计；Dense 向 Chroma 传 paper_id AND file_id metadata 预过滤。后端越界明确报错，不悄悄丢掉越界结果掩盖问题。
- **验证**：真实临时 Chroma 放入异论文相同向量，以及两篇共享关键词论文，越界块均不能进入结果；两篇 train 论文三路实际验收通过。
- **边界**：这是单论文检索，不是跨论文问答；全量 1,584 篇可选不等于每次联合检索全库。
- **面试要点**：隔离必须在候选召回前生效，不能只凭接口参数名猜实现。

### 15. Dense 返回分数不直接等于余弦；不同检索分数不能裸加【适配语义核验】

- **发现**：当前 Chroma adapter 使用 squared L2，并返回 exp(-distance)。
- **处理**：向量先验证有限/非零、转 float32、768 维 L2 归一化；再按 `cos = 1 + log(adapter_score)/2` 转换显示分数。这个转换仅对当前锁定空间/适配器成立。
- **融合**：复用 rank-bm25，而非从零手写；Hybrid 用两路各 Top-20 排名做 RRF，常数 60，不相加原始分数。跨路同 chunk 合并，路内重复报错，同分按 chunk_id 稳定排序。
- **验证**：BM25 公式、L2 分数转换、RRF 手算与边界测试；手算 a/b 同分得到稳定 `[a,b,c]`。
- **边界**：实现正确不证明 Hybrid 比 Dense/BM25 更好；没有正式质量对照结论。
- **面试要点**：先弄清分数方向、距离定义和量纲，再融合。

### 16. 文档、向量和身份关系不是一次原子提交【中断边界与修复】

- **风险**：嵌入失败、向量提交后关系表未提交、Source 身份创建后 metadata 未初始化，都可能留下半完成状态。
- **处理**：使用稳定 chunk ID、索引指纹、paper/file/chunk 映射，按已存在的文档/向量 ID 仅补缺失；嵌入完成后才标记 Source complete，未完成论文不允许检索。
- **审查后复现的缺陷**：Source 刚提交、note 为空的有效记录可能永久卡住。仅在原文件哈希一致、两类关系均为空时允许恢复初始化；冲突关系不能被接管。
- **验证**：真实临时存储覆盖嵌入失败续跑、向量先提交、Source 初始化中断；全量重复建库保持 1,584 篇/82,491 chunks，无新增编码日志。
- **边界**：这是针对已定义中断点的恢复，不等于实现跨库事务或处理所有故障。
- **面试要点**：幂等要看持久化状态，而不是简单判断“目录存在就跳过”。

### 17. 同名文件变化曾在写入后才被发现【复现并修复】

- **现象**：同名文件正文变化，原实现到关系集合校验才报错，此时已写入新 chunks。
- **处理**：复用 Source.path 的原文件 SHA-256，任何新写入前先比对，变化立即拒绝，要求显式新版本/索引。
- **验证**：`test_changed_file_rejected_before_any_new_chunks` 确认拒绝后存储数量不变，没有改真实语料来试错。
- **面试要点**：能报错不等于 fail-closed；关键是报错前有没有发生不应有的写入。

### 18. CLI --config 可能被注册工厂默认值悄悄覆盖【审查后复现并修复】

- **原因**：CLI 收到另一份配置，但共享 UI factory 仍读取默认配置，可能实际使用默认 k1 等参数。
- **处理**：构造 App 前明确拒绝与当前注册 UI 不一致的索引/检索配置，不静默替换。本版只有一份活动 UI 配置，实验切换需明确更换活动配置和独立 collection。
- **验证**：`test_cli_rejects_settings_different_from_registered_ui`；实际 CLI 与注册 UI Top-5 IDs 一致，重复查询一致。
- **面试要点**：脚本接收参数不代表底层执行生效；必须验证实际链路。

### 19. UI 的 0.0 融合分不是检索没命中，也不是置信度【实际观察，T5 修展示】

- **现象**：上游将约 0.03226646 的 RRF 分数四舍五入成 0.0，另有 Relevance score 标签容易误导。
- **处理**：T4 保留统一返回值里的精确分数并记录显示问题；T5 才改成八位小数，标注“非置信度”。
- **验证**：实际 CLI 原始结果和 T5 网页显示。不能把 T5 修复倒写为 T4 已完成。
- **面试要点**：先查原始结果，区分数值计算错误和展示精度问题。

## 建议优先准备的四个深挖题

1. **怎么保证只查选定论文？** 解释 pre-filter、paper_id/file_id 双约束、BM25 局部统计，以及相同异论文向量的反例测试。
2. **建库中途失败怎么办？** 解释稳定 ID、complete 状态、文档/向量/关系分开提交的中断点、幂等补齐和不接管冲突数据。
