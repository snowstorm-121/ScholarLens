## 1. 项目首页还停在 T6/T7

**现象：** 根 README 写“正式评测尚未运行”，V2 使用说明写“Test 未评分”，与已有 T8 首次结果冲突。**原因：** 实验报告更新后，项目入口文档未同步。**处理：** 以 `reports/test.md` 和 `reports/dev-retrieval.md` 为事实来源改写入口状态，明确分母、失败、论文范围与助手审查限制；历史 T2/T7 段落保留为阶段记录。**验证：** 核对 README 中数值和 T8 报告一致，不把 100 题生成子集与 300 题检索集混为一谈。

**面试要点：** README 是对外契约，数字必须能追到不可覆盖的原始运行记录；“有引文”不是“答案正确”。

## 2. 新进程打开设置页报 `KeyError`

**现象：** 选定配置启动应用后，设置页加载已保存的 `default` 用户设置，报 `KeyError: 'index.options.3.scholar_method'`。**根因：** 旧数据库行只保存了 `index.options.2.scholar_method`，新增索引选项已有当前默认值，但 `SettingsPage.load_setting()` 用旧行整体替换了当前 defaults。**处理：** 先以只读方式核对当前默认键与保存行，再加定向回归测试复现异常；把加载改为 `{**current_defaults, **saved_settings}`，让旧用户设置覆盖同名键，同时补齐后来新增的默认键。没有删除或重写用户设置数据库。

**验证：** 回归测试先红后绿；修复后新进程真实 UI 成功打开并完成引用问答。改动仅在 `libs/ktem/ktem/pages/settings.py` 一行，另加测试；不触碰冻结 Test 的检索、生成和评分路径。

**面试要点：** 配置 schema 演进时，旧持久化快照不能无条件替换新版本 defaults；补默认和迁移数据是两种不同策略，这里选择最小兼容修复。

## 3. 录屏捕获了错误前台

**现象：** 浏览器自动化能控制 ScholarLens 标签页，但 macOS 录屏捕到另一前台页面；再试又捕到 Codex。**原因：** 自动化选中标签页与系统前台窗口不是同一状态，发出终端录屏命令也可能改变焦点。**处理：** 检查试录缩略图，立即删除所有试录文件；没有把含无关页面的视频保存到项目或发布。QuickTime 界面控制未得到稳定结果，故停止试录，留下真实 UI 演示步骤并把视频明确标为未完成。

**面试要点：** 演示材料也需要验收：先检查画面与隐私，再判断能否交付；自动化“执行成功”不等于视觉产物正确。

## 4. 三种错误不能统称“模型不好”

`t9-failures.md` 保留了 Top-10 无 gold、正确证据排第 6 被 Top-5 排除、Top-1 已有 gold 但模型拒答三个实际案例。排查顺序是原文证据 → chunk/span → 排名 → context → 生成与引用。不能在看 Test 后针对个例修改本版参数，又继续宣称是首次冻结 Test。
