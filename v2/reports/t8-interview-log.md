# T8 正式 Test：问题、处理与面试复盘

日期：2026-10-16。代码、跑批、固定 20 题引用核查由助手按用户委托完成；不写成用户独立实现或独立人工审核。正式结果见 [Test 报告](test.md)。未受本次授权推送 GitHub。

## 1. 冻结配置与 Test 开锁如何兼容？

- 现象：T7 已冻结 `selected_config.json`，其中 `ready_for_test=false` 且保存旧版 `evaluate.py`/`cli.py` 哈希；评测器自身又把 Test 入口写死为拒绝。
- 风险：直接修改冻结配置并假称哈希没变，会失去实验可追溯性；无约束打开 `--split test` 又容易运行多次、换参数挑结果。
- 处理：保留 T7 配置原件与哈希，新增 `configs/t8-test-contract.json`，在看 Test 分数前登记四个唯一批次 ID、方法/阶段、配置、Test 文件和全套项目源码哈希；CLI/评测器只在合法契约下开放 Test，禁止 `--limit`，结果目录不覆盖首次预测。T7 内嵌源码哈希标明是历史快照，正式 Test 由 T8 契约记录新版哈希。
- 验证：缺契约、错误方法、`--limit`、文件哈希变化均由定向测试拒绝；四个实际 manifest 的契约哈希相同，配置和 Test 哈希评测前后未变。
- 面试要点：冻结的是实验条件和版本，不是“从此不能修运行入口”；工程变更必须独立版本化，且不能在看 Test 后改评分/模型再沿用原结论。

## 2. 本机端口访问失败，不等于 Ollama 没启动

- 现象：受限终端中的普通 `curl` 请求本机 11434 返回 exit 7，但端口监听存在；用户已启动桌面应用。
- 排查：获准以有本机端口权限的调用读取 `/api/tags`，确认 Ollama 与两个已安装模型的 digest 均匹配冻结配置。
- 处理：没有重装软件或下载模型；正式评测在可访问本机服务的执行环境中运行。
- 面试要点：区分服务状态、进程网络权限和模型版本。连接失败不能直接推断为应用未安装。

## 3. 依赖的冗余 NLTK 下载检查

- 现象：LlamaIndex 导入时检测旧 `tokenizers/punkt` 路径并触发 `nltk.download("punkt_tab")`，即使包内实际已有可工作的 `punkt_tab/english` 与 stopwords。
- 处理：沿用 T7 已验证的本地 tokenizer 资源；只在本次 Python 进程把该冗余下载调用改为空操作，然后正常导入和运行真实分词/检索。未改第三方包、未下载数据，也未改变 tokenizer 结果。
- 面试要点：遇到“缺资源”提示，检查真正使用的路径和功能，不凭一个下载提示就改变正式实验环境。

## 4. 会话中断时，不能盲目重跑 100 题

- 现象：生成批次运行时控制会话被中断；后台进程可能继续，也可能停止。
- 处理：先数逐题 JSON，再检查 summary；发现 100/100 题及汇总均已完整发布，因此没有重新执行或覆盖。若不完整，原设计只允许同契约 `--resume`，跳过首次结果。
- 验证：`scripts/t8_verify.py` 复算 100 条结果，逐题和 summary 一致。
- 面试要点：任务会话状态不等于实验进程状态；恢复前先查事实，避免二次模型采样污染一次 Test。

## 5. 官方整批分数与逐题平均“不同”

- 现象：离线核验最初使用浮点数严格 `==`；Answer F1 为 `0.3346767786226122`（逐题平均）与 `0.33467677862261225`（官方整批），断言失败。
- 原因：同一批数字累加顺序不同造成约 `5.6e-17` 的浮点舍入差；Evidence F1 一致。不是评测规则或预测不同。
- 处理：验收断言改为 `math.isclose(..., abs_tol=1e-12)`，保留逐题数据和官方评测器不变。
- 验证：官方整批复算与项目汇总在该数值容差内一致；四批原文、context、prompt、wire 参数和代码/数据哈希均核对通过。
- 面试要点：先量化差异再修断言；不能因浮点末位差就改 Test 答案或指标公式。

## 6. 真实质量问题必须留在正式结果里

- 9/100 次 `output_truncated`，不重试、不调高 `num_predict=512`；计入系统错误。
- 80 道可回答题中 22 次拒答，其中固定样本的 `0bde3ecf…` 与 `610fc593…` 已有完整 gold context 却仍拒答，属于生成/证据使用问题。
- 20 道无答案题中 17 次正确拒答、3 次错误回答；不能把 3 次回答转称“部分成功”。
- 固定样本 `16cc37e4…` 的引文本身能支持答案，但与 gold span 覆盖为 0；“引用可追溯”和“命中标注证据”必须分别报告。
- 固定样本 `6d55e377…` 有 1/3 条引用有效但整体协议无效；不能用一条有效证据包装整段答案。
- 面试要点：Test 的作用是暴露泛化与失败边界。看完 Test 可以提出下一版本假设，但本版不能继续调参后还称其为首次正式 Test。

## 7. V0 环境没有 pytest，不代表旧测试不可运行

- 现象：旧 conda 环境执行 `python -m pytest` 返回 `No module named pytest`。
- 处理：检查旧测试使用 Python 标准库 `unittest`，改用同一旧解释器运行 `python -m unittest discover -s tests -q`；11 项通过，没有为验收临时安装依赖。
- 面试要点：先识别项目真实测试框架与解释器；不要把测试入口缺依赖误报为代码失败。
