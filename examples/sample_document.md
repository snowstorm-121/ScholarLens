# 可追溯 RAG 示例文档

## 文档切分

检索增强生成系统首先将原始文档转换为可检索的文本块。固定字符切分实现简单、结果稳定，适合作为透明基线；重叠窗口可以减少关键信息恰好落在边界时造成的语义缺失。每个文本块除正文外，还应保留来源文件、块编号和块序号等元数据。

## 向量检索

Embedding 模型将文本块和用户问题编码到同一向量空间。查询时，系统计算查询向量与文档向量之间的余弦相似度，并按得分从高到低返回 Top-k 文本块。向量矩阵第 i 行必须始终对应文本块文件中的第 i 条记录；如果数量不一致，系统应当停止而不是继续返回可能错位的结果。

## 可追溯记录

可追溯检索不仅返回文本，还保留来源名称、文本块编号、相似度得分、拼接后的上下文和最终 Prompt。将这些中间结果写入 JSON 后，可以复盘一次问答究竟检索了什么、生成器看到了什么，以及答案是否具有来源支持。

## 当前边界

这个示例使用 dense vector retrieval 和固定字符切分，没有实现关键词混合检索、重排或查询改写。生成阶段使用 MockGenerator，它不会调用真实语言模型。该设计的目的不是模拟完整产品，而是提供一个结构清晰、行为可测试、结果可审计的 RAG 基线。
