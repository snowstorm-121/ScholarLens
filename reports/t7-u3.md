### 案例 A：RQE 方法

- 文件：`d98847340e46ffe381992f1a594e75d3fb8d385e.json`
- 问题：What machine learning and deep learning methods are used for RQE?
- 已观测：EvidenceRecall@5 = 1，Context EvidenceRecall = 1；`status=error`，`error.type=output_truncated`，`error.stage=generation`。
- `context_tokens=1295`，`dropped=[]`；`response.eval_count=512`，`response.done_reason=length`。固定输出上限为 512 tokens，窗口为 8192 tokens。
- 参考答案列出 Logistic Regression 和 neural networks。原始输出除这两项外，还展开了多个网络及相关工作的细节。
- 原始输出已有 `FINAL ANSWER` 和 `【1】`，并非空答案。`citations_parsed=0`、`citation_eligible=0`；冻结策略仍将长度截断记为错误，官方 Answer F1 / Evidence F1 均为 0。请阅读完整输出与上下文后再判断。

请填写：主要问题属于检索／上下文／生成／引用中的哪一层？是否还有次要问题？写出支持判断的字段或原文，并解释“gold 覆盖为 1”能证明什么、不能证明什么。

判断与证据：**主要问题在生成层，伴随答案范围/引用支撑不足。** `EvidenceRecall@5=1` 表明标注 gold span 已进入 Top-5，`Context EvidenceRecall=1` 表明它也出现在实际 context；`context_tokens=1295`、`dropped=[]` 说明没有因上下文预算被删掉。不能把这次失败归因于漏检或 context 丢失 gold。响应 `eval_count=512` 且 `done_reason=length`，对应固定 `num_predict=512` 上限，记录按冻结规则为 `output_truncated`，所以官方 Answer F1 / Evidence F1 仍为 0。输出虽已有 `FINAL ANSWER` 和 `【1】`，不能说模型完全没答；但答案把 Related Work 中的 siamese、Bi-LSTM、GRU、CNN、LSTM 等细节扩写成本文 RQE 方法，超出 gold 所支持的“Logistic Regression 与 neural networks”两类方法。引用块【1】指向 gold 段落，却不能支撑所有扩展细节；而该失败记录的冻结指标 `citations_parsed=0`、`citation_eligible=0`，不能据 raw 输出外观宣称引用验收通过。

`EvidenceRecall@5=1` 能证明本题标注的 gold evidence 被检索进入 Top-5；`Context EvidenceRecall=1` 再证明它出现在实际 context。两者都不能证明生成完整、答案事实正确、每句引用充分，也不能推广到其他问题。

### 案例 B：压缩方法的比较对象

- 文件：`efe9bad55107a6be7704ed97ecce948a8ca7b1d2.json`
- 问题：What state-of-the-art compression techniques were used in the comparison?
- 已观测：EvidenceRecall@5 = 0，Context EvidenceRecall = 0；`status=invalid_output`。
- 参考答案列出 NoKD 与 Patient Knowledge Distillation（PKD）；模型回答 dual training 与 shared variable projections。
- 原始输出的 `END_PHRASE` 为空；`citation_errors` 包含 `citation_1:missing_quote_phrases` 与 `answer_references_undefined_or_invalid_citation`。
- 实际上下文中仍有 Results 段落提到 PKD 和 NoKD baselines。请同时查看这一段与模型引用的 Introduction 段落。
- `citation_compliant=1`，但 `citations_valid=0`；不要把格式指标直接理解为引用有效或答案正确。

请填写：哪些是检索／上下文／生成／引用问题？是否可以只归因于“没检索到答案”？仅补上 `END_PHRASE` 是否足以回答原问题？分别引用原文说明理由。

判断与证据：**检索/证据层存在缺口，生成发生比较对象混淆，引用解析失败，不能只归因于“完全没检索到答案”。** `EvidenceRecall@5=0`、`Context EvidenceRecall=0` 说明标注的完整 gold span 未进入当前 Top-5/context；但 Top-5 的 Results 段实际写有 “NoKD baselines” 和 “PKD baseline”，所以 context 并非毫无线索，只是没有 gold 段落提供的完整比较说明。模型回答 “dual training and shared variable projections”，而 Introduction 引用段写的是作者提出的方法；Results 段则把 PKD/NoKD 明确称为 baselines。这是把“本文提出的方法”答成“比较中使用的技术”的生成归属错误。原始引用的 `END_PHRASE` 为空，且记录含 `missing_quote_phrases`、`answer_references_undefined_or_invalid_citation`，所以 citation 解析无效；`citation_compliant=1` 只表示该口径下的格式合规，不能推出引用有效或答案正确。

仅补 `END_PHRASE` 不足以回答原问题：它最多修复引用片段解析；若仍引用 Introduction 的本文方法段，引用依然不支撑比较基线，答案对象也仍然错误。更好的证据应来自明确列出 NoKD 与 PKD 的比较段（当前标注 gold 在该论文的 s9:p1），并由模型准确区分作者方法和基线。

## 审计回归测试

目标：验证**错误输出也不能绕过原文证据审计**。仅修改 `tests_scholarlens/test_t7_verify.py`，使用已有 `saved_example()` 和 `verify_prediction()`；不要修改 `scholarlens/*.py`、配置、原始实验记录或当前评测参数。

输入与操作：

1. 调用 `saved_example()`，取得 `row, papers, settings`。
2. 将 `row["status"]` 改为 `"error"`，模拟截断等错误状态；这不是实际调用模型制造截断。
3. 用已有的 `copy.deepcopy` 为 `row["prediction"]["context_chunks"]` 建立独立副本。随后仅篡改其中一个块的 `text`；保留检索结果、原文 `papers`、span 元数据和 prompt 不变。
4. 使用 `pytest.raises(AssertionError)`，断言 `verify_prediction(row, papers, settings, "generation")` 拒绝这条记录。测试函数名由你命名。

预期输出：新增测试通过，表示核验函数确实拒绝了被篡改的错误记录。这里“测试通过”不是“篡改记录通过核验”。若测试失败，先阅读异常与断言位置，不要为了通过而放宽核验逻辑。

在 V2 根目录运行：

```bash
.venv/bin/python -m pytest tests_scholarlens/test_t7_verify.py -q
```

命令含义：用项目虚拟环境的 Python 运行 pytest，仅检查这一份测试文件；`-q` 简化输出。它使用合成样例，不调用模型，也不运行 Dev/Test 评测。

实现说明：`saved_example()` 将同一个 chunk 对象同时放入 `context_chunks` 和 `metric_retrieval_results`。先对 context chunks 做 `deepcopy`，再篡改其文本，能只测试实际 context 与原文 span 的一致性，不连带改写检索审计记录。状态设为 `error` 是为了覆盖截断等部分失败记录；错误可能发生在生成阶段，但此前已产生的检索与 context 仍是审计事实，不能因最终状态为 error 就跳过核验。
